## Conventions

- The browser only ever calls the app's own address. `next.config.ts` rewrites `/v1/auth/*` and `/transactions-api/*` to the two services, whose addresses come from `AUTH_API_BASE_URL` / `TRANSACTIONS_API_BASE_URL` (or the `NEXT_PUBLIC_*` equivalents) — never from a literal in application code.
- Authentication is cookie-session only: no token or credential in browser-reachable state, no auth header from the API client. Server-side calls forward the incoming `session` cookie explicitly.
- Authorisation is re-resolved per server-rendered navigation from `GET /v1/auth/userinfo`; nothing caches roles.
- Test/mock factories in `web/src/mocks/data/` re-export the production types and role constants rather than declaring their own, so mocks cannot drift from the app's contract.
- Forms compose the Shadcn `form` primitive with react-hook-form and a Zod schema from `lib/validation/schemas.ts`. Required-field checks report on blur (`mode` and `reValidateMode` both `'onBlur'`, `noValidate` on the `<form>`), server-checked rules on submit; nothing reports on a keystroke. Required fields carry an `aria-hidden` asterisk in the label plus one legend line per form.
- A failed request's message is shown to the user only when it came from the service (`serviceMessageOf`); otherwise the screen supplies its own plain wording.
- Every screen needing a session is a page under `web/src/app/(authenticated)/`. That group's layout is the only gate (`force-dynamic`, `await requireSession()`) and renders the shared header; a new protected screen adds a page there and re-gates nothing.
- The root layout renders no `<main>`. Each screen supplies its own, so the app header stays a sibling of `main` and keeps its `banner` landmark.
- Header/user menus are non-modal (`modal={false}`): a modal Radix menu marks the rest of the page `aria-hidden` while it stays focusable, which fails the accessibility scan.
- Authorisation for a screen lives in `lib/auth/access-map.ts` and nowhere else. An epic shipping a screen registers or edits its address there, and its page returns `<PermissionDeniedMessage deniedPath={…} />` when `canAccess(session, path)` is false, before rendering anything — no second gating mechanism, no client-side gate. An address is registered before its screen exists so a denial can never fall through to not-found.
- Screens offer only what the current roles allow, as real links carrying an `href` (never a button that pushes a route), and an excluded action is left out of the markup rather than rendered disabled.
- The Shadcn `alert` default variant is the one used, with its description set to `text-foreground` and its title's one-line clamp released: the destructive variant paints the description at reduced opacity, which misses AA contrast for wording the user must act on.
- Every colour, the type face and the corner radius live in `web/src/app/globals.css` as raw-hex tokens, with a value in both `:root` (light) and `.dark`. Beyond the Shadcn set it declares `--success` / `--warning` / `--info`, `--destructive-foreground`, `--brand-accent` / `--brand-tertiary` (each with a paired foreground) and `--overlay` (the dim behind a modal), so a status, brand or modal surface never needs a Tailwind palette utility or a colour keyword. Components carry no colour value — including the CLI-generated primitives in `components/ui/`.
- Filled brand and status surfaces take the theme's own text colour as their foreground, not white: the brand blues are light, so `bg-primary text-primary-foreground` clears 4.5:1 in both themes only that way. `--input` is darker than `--border` so a field's outline clears 3:1 (WCAG 1.4.11).
- The light/dark version is expressed as the `dark` class on `<html>` and is resolved by the blocking inline script the root layout embeds in `<head>` — before first paint, never in an effect. A new screen needs no theme work; a new provider stack must not be nested around the root layout to add one.
- Browser state that already exists before React runs (the theme class, storage, a media query) is watched with `useSyncExternalStore`, never copied into React state by an effect: the lint rule `react-hooks` rejects setting state inside an effect, and a copy can disagree with what is on screen. Where the server cannot know the value, the server snapshot is the honest "not known yet" and the render handles it.
- The app's face is loaded once by `next/font` in the root layout as a CSS variable (`--font-cabin`) and reached only through the `--font-sans` token; no component names a font family.
- jsdom implements no `window.matchMedia`, so `vitest.setup.ts` supplies one that matches nothing (i.e. the light theme). A test that depends on a particular media query stubs it for that test only.
- Playwright alert queries are scoped to a region (e.g. `getByRole('main').getByRole('alert')`): Next.js renders its route announcer as a permanently empty body-level `role="alert"`, so an unscoped query always matches two elements.
- The `(authenticated)` layout notifies the user through the root layout's `ToastProvider`, so a test rendering that layout renders it inside the provider + `ToastContainer` composition the running app always has around it.
- A message the user is given twice — once as a notification when something happens, once as text on the screen they land on — is a live region only the first time: the copy on the destination screen takes `role="note"` so a screen reader is not told the same sentence again.

## Cross-epic debt

- CORS on both backends is an open backend requirement (project.md NFR-base-6). The same-origin rewrites make it a non-issue for browser calls; any future direct browser-to-service call would reintroduce it.
- `/upload` and `/requests` are registered in the access map but their screens ship in later epics: a permitted user following either entry point reaches not-found until then (each page's `notFound()` is what that epic replaces).
- `/requests` is seeded Approver-only. The `expense-request-list` epic must widen it to both roles (requirements R86/R87 give both read access to the list and its export) while keeping the decide actions Approver-only inside the screen.
- `next.config.ts` rewrite destinations are resolved at BUILD time and baked into `.next/routes-manifest.json`, so `AUTH_API_BASE_URL` / `TRANSACTIONS_API_BASE_URL` in the running server's environment do not move a browser-side `/v1/auth/*` or `/transactions-api/*` call. Two consequences every epic inherits: one built artifact cannot be promoted across environments, and the `E2E_PROD=1` Playwright mode cannot point browser-side calls at the stub, so Story 3's two sign-out specs fail there while passing in dev mode (they pass in prod mode when the build itself is given the stub URL). Fix is a request-time proxy route handler reading the base URL per request; it also changes the rewrite contract Story 1's committed spec pins. See `generated-docs/template-feedback.md`.
- `web/src/components/ui/alert-dialog.tsx` (Shadcn CLI output) has its overlay changed from `bg-black/50` to the `bg-overlay/60` token; regenerating that primitive will reintroduce the colour keyword.
- `web/src/components/ui/button.tsx` (Shadcn CLI output) hard-codes `text-white` on its destructive variant. Kept as-is because white clears 4.5:1 on the destructive red in both themes, where `--destructive-foreground` would not on the variant's `dark:bg-destructive/60` tint; regenerating that primitive will reintroduce it.
